# Contributing

## Branches

- `main`: always demonstrable;
- `feature/<short-name>`: product work;
- `fix/<short-name>`: defect fixes;
- `docs/<short-name>`: documentation-only changes.

## Definition of Ready

A task is ready when it has a user outcome, acceptance criteria, API/schema impact, owner, and test approach.

## Definition of Done

A change is done when it satisfies acceptance criteria, keeps OpenAPI synchronized, passes lint/type/test checks, includes error states, and updates documentation where required.

## Commit style

Use concise conventional commits, for example `feat(api): add project contract`.

## Pull requests

Keep pull requests focused. Include scope, screenshots or API examples, tests performed, risks, and rollback notes.
