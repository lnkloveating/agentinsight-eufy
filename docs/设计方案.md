# 前端 Agent 工作台全量设计方案

## 1. 目标

本次重构的目标不是继续给现有首页加模块，而是重定义整个前端工作台的页面职责。

需要同时达成 4 件事：

1. 首页从“信息堆叠页”改成“分发页”
2. 单项目页成为真正的执行工作台
3. 创建研究从首页主体降级为动作入口
4. 整体视觉从“泛后台 + 大表单”收敛为“研究调度台”

一句话定义：

首页负责把用户送到最该处理的下一步，项目页负责让用户完成具体工作。

---

## 2. 参考原则

本方案吸收以下成熟产品的优点，但不直接照搬外形：

- `Linear`
  - 首页克制
  - 优先展示下一步动作
  - 详细内容进入具体工作视图
- `GitHub Projects`
  - 同一批信息通过不同视图组织
  - 不把表格、时间线、指标全部摊平在首页
- `Multica`
  - 强调活动流
  - Agent 被视作工作成员
  - 重点是任务推进而不是聊天

---

## 3. 信息架构

建议将产品结构重构为三层。

### 3.1 全局层

负责一级页面切换。

建议固定左侧导航：

- 首页
- 项目
- 指标
- 报告
- 新建研究

说明：

- 一级导航只负责切换页面
- 不承担项目细节
- 不承担审批内容
- 不使用纯图标，统一采用“图标 + 文字”

### 3.2 首页层 `/projects`

负责分发，而不是承载全部内容。

首页只回答三个问题：

1. 现在最该处理什么
2. 哪些项目还在推进
3. 最近发生了什么变化

### 3.3 项目层 `/projects/:id`

负责单项目执行。

项目页才是完整工作台，承担：

- Brief 审阅
- Live Research 观察
- Evidence 检查
- Concept 决策
- Proposal 审批

---

## 4. 页面改造方案

## 4.1 App Shell

### 结构

```text
App Shell
├─ Sidebar
│  ├─ 首页
│  ├─ 项目
│  ├─ 指标
│  ├─ 报告
│  └─ 新建研究
└─ Content
   ├─ Page Header
   └─ Main Content
```

### 目标

- 建立稳定的全局骨架
- 让首页、项目页、指标页具有统一感
- 降低页面之间跳转时的认知切换

---

## 4.2 首页 `/projects`

首页是“研究分发页”，不是“完整驾驶舱”。

### 推荐结构

#### A. Hero

保留极简标题区：

- 次标识：`AgentInsight × eufy`
- 主标题：`研究驾驶舱`
- 极轻状态条：
  - `待审批`
  - `进行中`
  - `最近更新`

要求：

- 不放厚重统计卡
- 不放说明性长文案
- 不放按钮组

#### B. Next Action

首页最重要的模块，只显示一条最值得处理的事项。

展示内容：

- 项目名
- 当前堵点
- 当前 gate
- 主按钮：`立即处理`
- 次按钮：`查看项目`

展示规则：

- 永远只显示 1 条
- 如果没有待审批，则降级显示“最近进行中的项目”

#### C. Continue Working

展示最近 3 个项目，作为快速回到上下文的入口。

每张卡只保留：

- 项目名
- 当前阶段
- 状态标签
- 更新时间

不显示：

- 长描述
- 指标摘要
- 风险列表
- 多个按钮

#### D. Recent Activity

展示最近 5 条动态。

每条只保留：

- 动作主体
- 动作类型
- 时间

例如：

- `用户研究 Agent 完成场景聚类`
- `Portable Privacy Hub 等待 Concept gate`
- `新增 2 条有效证据`

#### E. Create Project

不再常驻首页。

改为：

- 左侧导航底部按钮
- 或首页右上角入口按钮
- 点击后打开 `Sheet` / `Dialog`

### 首页必须移出的内容

- 完整创建表单
- 详细项目长列表
- 详细指标
- 详细证据
- 概念对比细节
- 报告正文

---

## 4.3 创建研究

创建研究从首页主体降级为一个动作。

### 推荐交互

- 点击 `新建研究`
- 右侧弹出 `Sheet`
- 使用 3 段式表单

### 表单结构

#### 第一段：核心问题

- 核心问题

#### 第二段：基础范围

- 品类
- 目标用户
- 区域

#### 第三段：高级范围

- 场景
- 约束
- 焦点维度

### 规则

- 默认先展开“核心问题 + 基础范围”
- “高级范围”默认折叠
- 避免首页首次加载就展示完整大表单

---

## 4.4 项目页 `/projects/:id`

项目页是核心执行台。

### 推荐结构

#### A. 项目头部

保留：

- 项目名
- 当前阶段
- 状态标签
- 最近更新时间
- 主动作按钮

#### B. 项目内 Tabs

保留 5 个核心视图：

- Brief
- Live
- Evidence
- Concepts
- Proposal

#### C. 右侧上下文栏

固定承载：

- Agent 状态
- 待审批事项
- 风险提醒
- 最近事件

### 原则

- 首页不再重复项目页细节
- 所有深度内容都收敛到项目页完成

---

## 4.5 报告页 `/projects/:id/report`

报告页要像阅读页，而不是后台卡片页。

### 推荐结构

- 左侧正文
- 右侧证据引用
- 顶部审批状态

### 不建议

- 在报告页重复显示过多过程指标
- 在报告页使用过重的表单组件

---

## 4.6 指标页 `/projects/:id/metrics`

指标统一收敛到指标页，不回流首页。

### 推荐内容

- 方法对比
- 效率指标
- 质量指标
- 成本指标

### 目的

- 让首页更克制
- 让指标阅读更集中

---

## 5. 视觉方向

整体视觉定义为：

`策略研究室 + 调度工作台`

不是：

- 聊天机器人界面
- 营销着陆页
- 泛用 BI 仪表盘
- 管理后台表单页

### 视觉关键词

- 克制
- 有层级
- 高密度但可扫描
- 文字优先
- 结构优先于装饰

---

## 6. 信息密度规则

首页必须执行以下硬规则：

### 模块数量

- 第一屏一级模块不超过 3 个
- 首页总主模块不超过 4 个

### 卡片数量

- `Next Action` 只显示 1 条
- `Continue Working` 最多 3 条
- `Recent Activity` 最多 5 条

### 单条信息限制

一条首页卡片最多保留 3 个信息点：

- 名称
- 状态
- 时间或下一步

禁止在首页一张卡内同时塞：

- 描述
- 标签组
- 指标组
- 风险说明
- 操作说明

---

## 7. 组件重构清单

### 7.1 保留并继续使用

- `ProjectDecisionQueue`
- `ProjectActivityRail`
- `ProjectsListRail`
- 项目页现有工作区组件

### 7.2 需要降级或迁移

- `ProjectCreationPanel`
  - 从首页主体移到弹层
- 首页概览卡
  - 从厚卡改为轻量信息条

### 7.3 建议新增

- `AppSidebar`
- `NextActionPanel`
- `ContinueWorkingPanel`
- `CreateProjectSheet`
- `WorkspaceHeader`

---

## 8. 改造顺序

建议按以下顺序落地：

### 第一阶段

- 建立 App Shell
- 接入左侧一级导航

### 第二阶段

- 重写首页为分发页
- 保留 `Hero + Next Action + Continue Working + Recent Activity`

### 第三阶段

- 将创建表单移入 `Sheet / Dialog`

### 第四阶段

- 项目页头部重构
- 固定右侧上下文栏
- 统一 tabs 视觉层级

---

## 9. 验收标准

当以下条件成立时，说明本次设计改造完成：

1. 用户打开首页时，不会同时看到完整创建表单和多个重卡片
2. 首页第一屏能在 3 秒内判断“下一步做什么”
3. 用户能在首页直接进入待审批项目或最近项目
4. 首页不承担详细证据、概念、指标阅读
5. 创建研究成为动作入口，不再是首页主体
6. 单项目页成为唯一的深度工作区

---

## 10. 最终用户路径

重构完成后，理想路径应为：

1. 用户打开首页
2. 首页先提示最值得处理的事项
3. 用户进入目标项目
4. 在项目页中完成证据审阅、概念判断或最终审批

而不是：

1. 用户打开首页
2. 同时看到大表单、项目列表、状态块、动态块
3. 不知道先点哪里
