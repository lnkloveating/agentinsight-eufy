# 前端组件样式规范

本文档基于 `agentinsight-eufy` 当前前端实现整理，用于约束常用 UI 组件的样式语言与使用方式。

它与以下文档配套使用：

- [字体与字号规范.md](./字体与字号规范.md)
- [视觉基础规范.md](./视觉基础规范.md)

目标不是列出所有组件，而是先锁住最常用、最容易失控的基础部件，避免后续页面重新长成“通用后台”或“AI 聊天产品”。

## 1. 适用范围

优先约束以下组件：

- Button
- Badge
- Section Heading
- Sidebar Navigation
- List Row
- Form Field
- Input / Textarea / Select Trigger
- Tabs
- Card / Panel

## 2. 总体原则

- 组件首先服务信息结构，不服务装饰
- 同一类型组件在不同页面上不应长出完全不同的视觉语言
- 强调态依靠层级、字重、边框和少量颜色完成，不依赖重阴影
- 组件要克制，页面的重点应由布局决定，而不是由某个组件单独“喊出来”

## 3. Button 规范

### 3.1 主按钮

当前实现基线：

- 选择器：`.ui-button.ui-button--primary`
- 背景：`var(--accent)`
- 文字：白色
- 圆角：`999px`
- 最小高度：`42px`
- 内边距：`10px 16px`
- 阴影：无重阴影

适用场景：

- 当前主操作
- 审批主动作
- 关键跳转入口

约束：

- 同一区域通常只允许一个主按钮
- 主按钮不要同时和大面积蓝色面板叠加使用
- 不要把所有操作都做成主按钮

### 3.2 次按钮

当前实现基线：

- 选择器：`.ui-button.ui-button--ghost`
- 背景：半透明浅白
- 边框：`1px solid var(--border-strong)`
- 文字：`var(--text-main)`
- 圆角：`999px`

适用场景：

- 次级跳转
- 查看详情
- 辅助动作

约束：

- 次按钮应弱于主按钮
- 不要把 ghost 按钮做成与主按钮同等视觉重量

### 3.3 危险按钮

当前实现基线：

- 选择器：`.ui-button.ui-button--danger`
- 背景：`var(--danger)`
- 文字：白色

适用场景：

- 终止
- 删除
- 高风险确认动作

约束：

- 危险按钮只能用于真正不可逆或高风险动作
- 不要为了“显眼”滥用红色按钮

### 3.4 Hover 行为

当前实现基线：

- 不做明显上浮
- `transform: none`
- 只允许轻微颜色与对比变化

约束：

- 不要加入明显的弹跳、漂浮或夸张 hover 阴影
- 工作台风格应稳定、理性，而不是营销页式互动

## 4. Badge 规范

### 4.1 当前实现基线

- 选择器：`.ui-badge`
- 高度：`28px`
- 圆角：`999px`
- 横向内边距：`10px`
- 字号：`12px`
- 显示方式：inline-flex

当前色阶：

- `.ui-badge--neutral`
- `.ui-badge--accent`
- `.ui-badge--warning`
- `.ui-badge--danger`
- `.ui-badge--success`

### 4.2 使用原则

- badge 用于状态，不用于装饰
- 一条信息里 badge 数量尽量不超过 `2`
- badge 应该短、稳、可扫描

### 4.3 禁止事项

- 不要新增大量临时 badge 文案
- 不要一张卡片里塞满状态胶囊
- 不要把 badge 当成标题使用

## 5. Section Heading 规范

### 5.1 通用区块标题

当前实现基线：

- 选择器：`.section-heading`
- 布局：左右分栏，允许 action
- 默认下边距：`16px`

内部结构：

- `.section-heading__eyebrow`
- `.section-heading__title`
- `.section-heading__actions`

### 5.2 首页分区标题

首页当前使用两种机制：

- `.section-heading--accent-title .section-heading__title`
- `.home-section__title`

共同特征：

- 小字号
- 蓝色
- 高字重
- 英文大写
- 偏“功能分区”而不是内容标题

### 5.3 使用原则

- 标题负责定义区块身份，不负责承载大段解释
- 非必要不再给标题下方追加 description
- 标题区不要叠加统计卡、说明文案和大按钮

### 5.4 禁止事项

- 不要在每个区块标题下面都放描述文字
- 不要把标题区重新做成 hero
- 不要出现中文标题和英文标题双写一遍的情况

## 6. Sidebar Navigation 规范

### 6.1 当前实现基线

主要结构：

- `.app-shell__sidebar`
- `.app-shell__brand`
- `.app-shell__nav`
- `.app-nav-link`
- `.app-shell__collapse`

当前特征：

- 浅色半透明侧栏
- 轻边界
- 无厚阴影
- 图标 + 文字并行
- 支持折叠

### 6.2 一级导航规则

一级导航只用于页面切换，例如：

- 首页
- 项目
- 指标
- 报告

不承载：

- 复杂业务数据
- 最近动态
- 多层说明
- 大块统计

### 6.3 单项导航样式原则

当前实现基线：

- 高度偏紧凑
- 圆角：`14px`
- hover 只做轻底色变化
- 激活态使用浅蓝底 + 蓝字

约束：

- 图标与文字必须共同存在
- 纯图标导航只适合折叠态，不适合默认态
- 不要为 hover 添加重阴影

## 7. List Row 规范

### 7.1 适用对象

包括但不限于：

- 首页 `CONTINUE WORKING`
- 首页 `RECENT ACTIVITY`
- 项目列表
- 侧栏列表
- 动态时间线中的轻量条目

### 7.2 当前实现基线

共同特征：

- 轻边框容器
- 每一行顶部有分隔线
- 行内信息采用清晰的主次结构
- hover 只做极轻背景变化

### 7.3 行内结构建议

推荐按以下顺序组织：

1. 标识位
2. 主信息
3. 次信息
4. 时间 / 状态 / 跳转提示

### 7.4 使用原则

- 一行只表达一个主要对象
- 标题、状态、时间、阶段必须有主次关系
- 一行里尽量不要同时出现过多 badge、按钮、进度、说明

### 7.5 禁止事项

- 不要让 meta 区宽度无限膨胀
- 不要把整行做成复杂卡片
- 不要在列表中引入多套不同的对齐逻辑

## 8. Form Field 规范

### 8.1 当前实现基线

主要结构：

- `.ui-field`
- `label > span`
- `.ui-input`
- `.ui-textarea`
- `.ui-selectbox__trigger`
- `.multi-select-field__trigger`

字段特征：

- 垂直排列
- 标签在上
- 控件统一使用圆角浅底
- focus 用浅蓝描边光晕表达

### 8.2 标签规则

- 标签必须短
- 标签优先结构化名词
- 不要把解释型长句写进 label

### 8.3 输入框规则

当前实现基线：

- 最小高度：`48px`
- 背景：`var(--bg-panel-strong)`
- 边框：`1px solid var(--border-strong)`
- 圆角：`var(--field-radius)`

约束：

- 所有表单控件圆角统一
- 不要让原生系统 select 样式混入当前页面
- 不要出现一部分控件 16px 圆角、一部分控件 8px 圆角

### 8.4 Textarea 规则

- 最小高度：`108px`
- 允许纵向 resize

使用原则：

- 如果内容是短选项集，优先转成选择器，不要滥用大 textarea
- textarea 只留给真正需要输入多项信息的场景

## 9. Select / Multi Select 规范

### 9.1 Select Trigger

当前实现基线：

- `.ui-selectbox__trigger`
- 自定义 trigger，不使用系统原生视觉
- 与 input 同高度、同圆角、同边框语言

### 9.2 Dropdown Content

当前实现基线：

- 浅白底
- 轻边框
- 柔和投影
- 选项 hover 浅蓝底
- 选中项浅蓝底 + 蓝字

### 9.3 Multi Select

当前实现基线：

- 摘要显示在 trigger 内
- 右侧显示已选数量
- 展开层宽度受控，不铺满页面

使用原则：

- 优先让用户先看摘要，再决定是否展开
- 多选项命名要短
- 不要把多选器做成一整块复杂设置面板

## 10. Tabs 规范

### 10.1 当前实现基线

主要结构：

- `.view-tabs`
- `.view-tabs__item`
- `.view-tabs__item--active`

当前特征：

- 桌面下为轻胶囊或细线式切换
- 编辑型页面中更偏“文本 tab”

### 10.2 使用原则

- tabs 只用于同层级视图切换
- tab 数量应稳定，不要无限增加
- 文案应短且统一

### 10.3 禁止事项

- 不要在 tabs 内塞图标、数字、说明和操作按钮
- 不要把 tabs 做成按钮工具栏

## 11. Card / Panel 规范

### 11.1 当前实现基线

主要结构：

- `.ui-card`
- 首页的 `next-action-banner / home-work-list / home-activity-list`

当前特征：

- 浅白半透明
- 轻边框
- 大圆角
- 弱阴影甚至无阴影

### 11.2 使用原则

- 卡片用于组织内容，不用于制造存在感
- 一块卡片只承载一个主要主题
- 卡片内部信息点应收敛，不要越做越厚

### 11.3 首页特殊原则

- 首页不再堆砌“卡片中的卡片”
- `NEXT ACTION` 可以相对更强，但不能厚重
- `CONTINUE WORKING` 和 `RECENT ACTIVITY` 应更像列表容器，而不是独立营销卡片

## 12. 响应式规则

### 12.1 当前倾向

- 桌面优先
- 平板可读
- 手机优先保证可查看与可审批

### 12.2 组件级规则

- 按钮组可换行
- 列表行在小屏下应重新排栅格，而不是简单硬挤
- meta 区在小屏下允许下沉或左对齐
- 大容器 padding 在移动端需要同步收紧

### 12.3 禁止事项

- 不要仅依赖 `grid-template-columns: 1fr` 粗暴压缩所有组件
- 不要让响应式破坏主次信息顺序
- 不要让图标、状态、时间互相重叠

## 13. 组件新增与修改守则

后续新增组件前，优先判断：

1. 这是新组件，还是现有组件变体
2. 这类视觉差异是否真的需要新样式
3. 能否复用现有 `button / badge / list / panel / field` 语言

只有在以下情况才建议新增明显新样式：

- 新的交互模型完全不同
- 新的业务语义无法被现有组件承载
- 新组件不会破坏整体工作台语言一致性

## 14. Agent 自检清单

每次新增或修改组件时，先自检：

1. 这个组件是在解决结构问题，还是只是在增加装饰
2. 它是否还能被归入现有组件家族
3. 它的圆角、边框、颜色、间距是否仍然说同一种语言
4. 它是否让首页或工作台重新变拥挤
5. 它是否让页面更像通用 SaaS，而不是研究工作台

如果其中任意一项答案不理想，应继续收敛，而不是直接提交。
